# hype-checker v2 설계 — DM 공유 수신 (2026-10-26)

> 근거: research `requests/hype-checker-feasibility.md` §2-3·§4-4, ADR `~/Ops/adr/0011-hype-checker-v2-official-api-only.md`, Meta 공식 문서 원문 재확인(2026-10-26, §8 출처). v1 설계: `docs/design-v1.md`

## 1. 목표와 범위
- 내 전용 IG 프로페셔널 계정에 릴스·게시물을 DM으로 공유하면, v1 파이프라인이 **캡션으로** 측정 묶음을 만들고 짧은 요약을 DM으로 답한다
- **v2.0은 캡션만 처리한다.** DM으로 온 글은 `classify_remote`로만 분류한다 — 로컬 경로·`.mp4`·인스타·유튜브 링크는 전부 **텍스트로** 다루고, GitHub·npm·PyPI 링크만 읽기 전용 측정으로 보낸다(원격 DM이 이 맥의 파일 읽기나 다운로드를 일으키지 않게). 웹훅의 `url`은 서명된 CDN 링크(lookaside.fbsbx.com)이고 만료된다. 영상 내려받기는 실수신으로 url의 성격을 확인한 뒤(§7 ❓2·3) v2.1에서 따로 판단한다
- 판정·카드는 v1처럼 Claude 세션과 사람이 한다. v2는 입력 경로만 바꾼다
- 하지 않는 것: 비공식 API·쿠키·자동 댓글·oEmbed(ADR 0011), 남의 계정 대행(App Review 필요), 클라우드 배포

## 2. 구조
```
IG DM 공유 ─▶ Meta 웹훅 ─▶ Tailscale Funnel(HTTPS) ─▶ 127.0.0.1:8787 `serve`
                                                        │ 서명 확인 → 파싱 → 발신자 허용 목록 → 큐(out/v2/queue)
                                                        ▼
                                  `work` ─▶ v1 check(캡션) ─▶ out/<case>/bundle.md ─▶ 답장 초안(기본) / 전송(--send)
```
- 수신기는 **이 맥에서** 돌린다. 로컬 LLM·watch·gh 로그인이 여기 있고, 공개 입구는 Tailscale Funnel 하나다(ADR 0008에서 이미 쓰는 방식). 클라우드에 비밀값을 보관하지 않는다(답장 토큰은 Meta로만 전송된다)
- `serve`는 빨리 답한다(검증·큐 적재·200). 무거운 일은 `work`가 한다. Meta는 실패 시 36시간 재시도하므로 큐는 메시지 id로 중복을 거른다(처리 완료·격리 뒤에도). `serve`는 동시 연결 8개 상한의 스레드 서버이고, 요청 본문은 **전체 10초 기한** 안에 다 와야 한다(조금씩 흘려 보내는 요청도 끊는다). 큐 게시는 중복 검사와 한 잠금 안에서 한다

## 4. 처리 (`worker.py`)
- 큐는 원자적으로 게시(임시 파일 → rename)하고 파일 권한 600·폴더 700. `work`는 한 번에 하나만(파일 잠금). 읽을 수 없거나 허용 목록 밖 발신자인 큐 파일은 `failed/`로 격리하고 다음으로 넘어간다(로컬 큐 변조 방어). `done/`·`failed/`는 `work`를 돌릴 때마다 7일 지난 것을 지운다(`work`를 안 돌리면 남는다). 캡션이 들어간 `out/<case>/` 묶음은 v1 정책을 따른다(판정·카드 근거라 자동 삭제하지 않음, 프레임은 `clean`)
- 큐 항목마다 `check(caption, tag=mid)` → 묶음에 `dm` 블록(kind·media_id·url 유무)을 붙인다. **url 자체는 저장하지 않는다**(서명 링크·만료·보관 최소화)
- 캡션 속 지시(예: "npx ruflo init")는 v1과 같이 데이터로만 다룬다. 프로세스 실행은 v1 runner 허용 목록 그대로이고, v2 모듈은 프로세스를 띄우지 않는다(불변식 테스트)
- 한 항목이 실패해도 큐는 계속 돈다. 실패는 `done/`에 오류와 함께 남는다

## 5. 답장 (`reply.py`)
- 내용(2026-11-01 통일): 제목 + "도구 N개의 공개 위치를 찾아봤어요" + 판정 전 안내 + primary마다 `번호. "이름" · 종류` / `🔗 위치 · ⭐ 스타` 또는 상태 문구, 첫 ⚠️ 사실 한 줄 + 묶음 id. 표기는 `hype_checker/labels.py` 하나를 묶음(bundle.md)과 같이 쓴다. ✅❌는 사람 판정 카드 전용이라 쓰지 않는다. 형식은 `tests/test_golden_output.py`가 고정. **판정 문구(진짜·가짜)는 쓰지 않는다** — 판정은 사람 승인 뒤
- 1000바이트 상한(Send API), 24시간 창 안에서만 가능
- 기본은 **초안만** 만들고 `done/`에 남긴다. `work --send`는 새 항목과 **아직 안 보낸 초안**을 보낸다(외부 발송 → 처음 켤 때 사람 확인). 24시간이 지난 초안은 보내지 않고 사유를 남긴다
- **최대 1회 전송**: 호출 전에 시도 시각을 기록하고, 실패가 확인되면(HTTP 오류·429) 지워서 다음 실행에 재시도, 호출 중 종료되면 재전송하지 않는다
- 후보 이름은 게시물에서 뽑은 그대로라 악성 캡션이 "검증 완료" 같은 이름을 만들 수 있다 → 이름은 따옴표 안 한 줄로만 넣고 머리말에 "평가가 아니에요"를 적는다
- 엔드포인트 `POST https://graph.instagram.com/v26.0/me/messages`, `Authorization: Bearer <IG 토큰>`

## 6. 비밀값
- `~/.config/hype-checker/v2.env`(레포 밖), 권한 600이 아니면 거부
```
IG_VERIFY_TOKEN=<임의 문자열>
IG_APP_SECRETS=<App Secret>,<Instagram app secret>
IG_ALLOWED_SENDERS=<내 개인 계정 IGSID>
IG_ACCOUNT_ID=<전용 계정 IG ID, 권장>
IG_ACCESS_TOKEN=<답장용, 선택>
```
- 네트워크를 여는 모듈은 `http.py`(레지스트리 GET), `extract.py`(로컬 LM Studio), `v2/reply.py`(답장)뿐이다(불변식 테스트)

## 7. 실수신으로 확인할 것 (❓, 착수 조건)

## 11. Codex 반박 리뷰 반영표 (#2, 상한 도달)
| # | 지적 | 실측 | 판정 |
|---|---|---|---|
| 1 | P1 10초는 소켓 동작당이라 조금씩 흘려 보내면 무기한 점유, 연결 수 상한 없음 | 타당 | 수용. 본문 전체 기한(`read_body`), 동시 연결 8개 상한(`BoundedServer`) + 테스트 2건 |
| 2 | P1 스레드 서버에서 같은 mid 동시 수신 시 중복 검사·게시 경쟁, 같은 임시 파일 | 타당 | 수용. 검사+게시를 한 잠금으로, 임시 파일은 `mkstemp` + 동시 16건 테스트 |
| 3 | P1 시간 초과도 '확인된 실패'로 보고 재전송 → 최대 1회 아님 | ✅ 코드상 확인 | 수용. Meta가 거절한 경우(`SendRejected`, HTTP 오류)만 재시도, 그 밖은 "결과 불명"으로 다시 보내지 않음 + 테스트 |
| 4 | P2 완료 초안은 허용 목록 재검사 없이 전송 | 타당 | 수용. 전송 직전 현재 설정으로 재검사 + 테스트 |
| 5 | P2 `["mid"]` 같은 JSON·읽기 불가 파일이 worker를 멈춤 | 타당 | 수용. dict만 받고 격리 경로의 재읽기·삭제 실패를 흡수 + 테스트 |
| 6 | P2 600/700·7일 보관 주장이 실제보다 넓음 | 맞음 | 수용. 기존 폴더 권한 교정, 문서를 실제 범위로 고침(묶음은 v1 정책) |

**남는 위험(사람 판단)**: 헤더를 아주 느리게 보내는 연결 8개가 슬롯을 모두 잡으면 그동안 웹훅을 못 받는다(헤더는 소켓 동작당 10초 제한만 있음). 영향은 수신 지연뿐이고 Meta가 36시간 재시도하므로, Funnel 공개 뒤 실제 접속 로그를 보고 판단한다. Codex 리뷰는 review.md 상한(2회)에 도달했다.
