# design-v4 — 추천 점수 0~10, 더 유명한 대안, 결과 캐시 (2026-11-02)

사용자 결정(2026-11-02): 등급(👍🤔👎❔)과 점수를 **함께** 보인다 · 대안은 GitHub 검색 + Claude 확인 · 캐시는 릴스 7일, 도구 3일.

## 1. 추천 점수 (`score.py`, 코드만)
- 등급 = 게시물이 얼마나 확인됐나, 점수 = 도구 자체를 얼마나 권하나. **게시물 주장(일치·불일치)은 점수에 안 들어간다**(Codex 1차: 과장한 게시물 때문에 도구 점수가 깎이면 안 됨)
- 점수 없음("추천 판단 보류"): ❔, 또는 코드 측정이 없는 도구(원격 MCP·상용 제품 — 별이 없으면 근거가 없다)
- 기본 5. 스타(≥50k +3, ≥10k +2, ≥1k +1, <100 −1, <10 −2) · 업데이트(30일 안 +1은 스타 100 이상만, 180일 넘음 −1) · 경고(설치 스크립트·보안 권고·포크·보관·저장소 불일치, 최대 −2). 0~10으로 자름. 스타 급증은 안내만 한다(화제와 구매를 구분할 수 없어 감점·👍 차단 없음, 2026-11-03)
- **더 유명한 대안은 점수에 안 들어간다**(Codex 4차): 같은 기능인지는 Claude만 판단하고 코드로 검증할 수 없어서, 인젝션·오판이 점수를 바꾸지 못하게 소개(💡)만 한다
- 도구 자체의 빨간 신호(security holder, 사칭 복제)는 최대 3점. 답장에 "📊 기본 5점 · 업데이트 +1 … → 4점"으로 계산을 보인다

## 2. 더 유명한 대안 (`alternatives.py`)
- 후보: 도구의 구체적인 토픽(일반 토픽 제외, 긴 것부터 최대 3개)별 검색 + 설명 단어(자기 이름 제외) 검색. 스타 ≥ max(500, 내 스타×2), 포크·보관 제외, 1년 안 업데이트
- Claude는 목록의 id 중 "target 대신 설치해 같은 핵심 기능을 쓸 수 있는 것"만 고른다(확실하지 않으면 different). 목록 밖 id는 버린다. 설명 원문은 DM에 나가지 않고 id·스타만 나간다
- 실측: lux → yt-dlp(⭐204k) 찾음, agent-desktop → 없음(범용 에이전트·인프라는 제외)

## 3. 캐시 (`v2/store.py`, SQLite `/app/out/v2/hc.db`, 600, 열기 실패 시 캐시 없이 동작)
- 같은 게시물 → 7일 동안 저장된 답장을 다시 보낸다. 키 = 규칙·점수·주장 프롬프트 버전 + 모드 + HC_VERDICT·HC_VIDEO + 종류 + **media_id + 캡션 해시**. media_id가 없으면 캐시하지 않는다(다른 게시물 오답 방지). 판정이 `ok`로 끝난 것만 저장
- 다시 보낼 때 첫 메시지로 "같은 게시물을 N일 전에 확인한 결과… 스타 수 등은 그때 기준"을 붙인다
- `정정`을 받으면 그 발신자의 직전 답장 캐시를 지운다
- 같은 도구(identifier) → 공식 설명·대안을 3일 재사용. 주장 대조는 게시물마다 새로. **검색 실패·시간 초과·읽을 수 없는 응답은 '모름'**으로 두고 저장·감점하지 않는다
- 순서: 주장 대조(본업)를 먼저, 남은 예산으로 대안. 검색 사이마다 시간 예산을 확인한다. 캐시 읽기·쓰기 오류는 판정에 영향 없음

## 4. 답장 형식
- 요약 메시지 + 도구별 상세(🔗 링크 · ⭐/업데이트 · 👍 좋은 점 · ⚠️ 살펴볼 점 · 💡 더 유명한 도구 · 📊 계산). 상세는 생략 없이 다음 메시지로 이어 보내고 안내 문구는 항상 마지막(2026-11-02 메시지 수 상한 제거, `5e47a6a`)

## Codex 지적 처리 (상한 없이 차단 해소까지, 2026-11-02 사용자 지시)
- **아이템 전역 마감 180초**: 워커가 처리 시작 때 `LiveSources.deadline`을 정한다. gh(30초)·http(20초) 호출은 `min(자기 상한, 남은 시간)`, 남은 시간 1초 미만이면 호출 안 함. 검색 속도 대기가 마감을 넘기면 기다리지 않고 건너뛴다. DM watch는 `min(150초, 남은 시간)`(타임아웃 시 프로세스 그룹 종료). Claude 호출(화면 읽기·이름 추출·주장 대조·대안 판정)은 시도마다 한 호출(Claude 60초, 로컬 LM Studio 300초)이 통째로 남아 있을 때만. Claude·레지스트리 호출은 연결·헤더·본문·오류 본문까지 **전체 경과 시간**으로 끊는다(`http.call_within`, 넘으면 호출자는 넘어가고 버려진 데몬 스레드는 소켓 제한에서 끝남). 넘으면 그 단계는 '모름'으로 끝나고 답장은 그때까지의 결과로
- 대안: 목록·튜토리얼·책 저장소는 후보에서 뺀다. 고른 대안은 소개만, 점수 영향 없음. 캐시된 대안은 오늘 스타 기준(내 스타×2, 최소 500)으로 다시 거른다. Claude 장애·검색 실패·빈 응답은 '모름'(저장 안 함), 본업 판정은 그대로 나간다
- 공식 문서: fetch 실패(`failed`)는 저장하지 않고 판정을 `partial`로, 원래 없음(`none`)은 정상
- 릴스 답장 캐시는 **완전한 결과만**: 판정 `ok` + 이름 추출 `ok` + 영상 받기·읽기·화면 읽기 정상(시도했다면) + 주요 도구의 모든 측정이 failed·partial 없음 + 모든 대안 확인 끝. "잠시 뒤 다시 보내 주세요" 같은 실패 답장은 저장 안 함
- 도구 캐시는 공식 문서와 대안을 **각자의 저장 시각**으로 따로 만료한다(한쪽을 새로 저장해도 다른 쪽 수명이 늘지 않음)
- 이름 추출 중 Claude 장애·빈 응답, 처리 중 예외 모두 답장 없는 종료가 아니라 '지금은 처리하지 못했어요' 답장으로
- 처리 중 GitHub·레지스트리 조회가 하나라도 실패하면(404 제외, 시간 초과·속도 제한 포함) 그 답장은 캐시하지 않는다(식별·측정 실패가 '없음'으로 굳지 않게)
- 도구 캐시 키는 정확히 일치(`IN`), LIKE 와일드카드 없음. GitHub `owner/repo`만 소문자로 맞추고 MCP URL은 `urlsplit`으로 나눠 scheme·hostname만 소문자, 사용자 정보·포트·경로·쿼리는 그대로. 같은 키로 판정 대상 중복도 제거한다(`a/b-c`와 `a/bc`는 별개)
- 버려진 호출이 끝없이 읽지 않도록 응답 본문은 조각 단위로 읽으며 8MB·호출 자체 마감에서 멈춘다. 호출자는 항상 제한 시간에 돌아오지만, chunked 응답의 크기 줄을 기다리는 동안은 버려진 스레드가 더 남을 수 있다(데몬 스레드, 소켓 대기 단위로 진행 — 수용, P2)
- 성공 코드에 빈·깨진 본문(gh·레지스트리 모두)은 조회 실패로 기록. README 응답이 형식에 안 맞으면 `failed`, README는 됐는데 저장소 설명 조회만 실패하면 `partial`(이번엔 쓰되 캐시 안 함). 캐시된 대안은 오늘 스타를 모르면 '모름'
- 이름 추출 병합도 `owner/repo` 표기는 정확히 비교(서로 다른 저장소의 주장이 섞이지 않게). IPv6 주소도 소문자로 맞춤
- 캐시 정리와 토큰 갱신은 서로 독립(한쪽 오류가 다른 쪽을 막지 않음)
- 저장소 메타 측정이 실패하면 대안은 '모름'(저장 안 함). README가 원래 없는(404) 저장소는 저장소 설명을 공식 문서로 쓰고, 조회 장애일 때만 `failed`
- 목록·강좌 판별은 저장소 이름(소유자 제외)·토픽의 **단어**와 설명의 구절로만(`facebook/react`가 'book'으로 걸리지 않게)
- 사칭 신호는 표시 사유와 별개로 엔티티에서 직접 판정해 점수 최대 3점
- 대안 자체의 보안·설치 스크립트는 측정하지 않는다(소개만 하므로 추천하지 않음)
- 받음 알림은 처리 중 서버가 죽으면 다시 갈 수 있다(결과 답장은 1회 보장 유지)
- 이름 추출 병합: 표기가 다르면 식별 전에 합치지 않는다(글에 적힌 `owner/repo`·npm 패키지 보존). 두 청크 표는 추출 결과가 직접 연결한 별칭끼리만 공유하고, 같은 저장소로 확정되면 판정 단계에서 주장을 합친다
- 리뷰 종료(21회 뒤 사용자 지적): P0·P1이 없으면 끝낸다. 남은 P2: chunked 응답을 읽는 버려진 스레드가 더 남을 수 있음(호출자는 제한 시간에 돌아옴)
