## 1. 등급 정의 — "확인된 정도"
| 등급 | 뜻 | **필수 증거(전부 충족)** |
|---|---|---|
| 👍 확인됨 | 실재하는 공식 도구이고, 광고 주장이 공식 문서와 맞으며, 눈에 띄는 위험 신호가 없음 | ① 공식 위치 하나로 식별(`resolved`/링크) ② **코드 측정 있음**(GitHub 레포 또는 npm) ③ 최근 1년 안 활동 ④ ⚠️ 신호 없음 ⑤ 캡션 주장 중 `불일치` 0개, `일치` 1개 이상 |
| 🤔 주의해서 | 실재는 하지만 확인이 부족하거나 주의 신호가 있음 | 공식 위치는 하나로 식별됨 + 👍 조건 중 하나 이상 미충족. **원격 MCP·상용 제품(코드 측정 없음)은 최대 🤔** |
| 👎 권하지 않아요 | 강한 반대 증거가 있음 | 다음 중 하나: npm security holder(악성으로 내려진 이름) / 캡션 주장이 공식 문서와 **불일치**(원문 구절 인용 가능) / 캡션이 가리킨 대상이 원본이 아닌 사칭 복제로 확인(`원본 추정` 규칙이 다른 레포를 원본으로 지목) |
| ❔ 판정 보류 | 판정할 근거가 없음 | 공식 위치 못 찾음·후보 여럿·측정 실패·한도 초과 |

> **알려진 공백(Ruling 20):** "사칭 복제" 👎 조건은 현재 파이프라인이 검출하지 못한다. 후보의 `원본 추정` 태그는 이미 고른 식별자에만 붙고, 같은 이름의 다른 레포를 다시 찾아 원본과 비교하는 측정이 없다. 그래서 사칭 복제 사례는 지금 **최대 🤔**로 나온다(보수적 — 👍는 나가지 않음). 검출은 새 측정이라 v3 범위 밖이며, 정답셋 a03/a04는 사람 관문(T1 S5)에서 교체·재라벨한다.

- **2026-11-01 개정(규칙 v3)**: ⑤는 입력이 **링크만**일 때(캡션 없음)에만 면제한다. 캡션이 있으면 추출된 주장이 0개여도 면제하지 않는다 — v2("주장이 없으면 면제")는 추출이 주장을 놓친 Ruflo(정답 👎)를 👍로 내는 치명 오류를 만들었다(holdout 재실행, 정보용). 주장이 있는데 대조하지 못했으면(예산 소진·공식 문서 없음) 👍 불가. 근거: dev 평가 3회에서 👍 정답 4건이 전부 링크 입력이라 ⑤ 때문에 원천적으로 👍가 불가능했음
- 보안 권고·install 스크립트·레포 불일치·fork·archived는 **👎 사유가 아니라 🤔 사유**다(근거 줄에 그대로 적는다). 심각도·적용 범위를 코드가 판단하지 못하기 때문(Codex #2)
- "미측정"은 안전으로 해석하지 않는다 — 측정이 없으면 👍 불가
- 답장 고지: "자동 확인 결과예요. 기능이 좋은지는 직접 써 봐야 알아요. 설치 전 공식 페이지를 꼭 확인하세요."

## 2. 흐름
```
DM ─ webhook(v2 그대로) ─ queue ─ work --loop (항목 하나씩: 처리 → 전송, 마감 180초)
   ① check(caption)        추출(+주장) · 식별 · 측정 → bundle.json            [v1/v2 + claims]
   ② official_text         식별된 공식 위치의 설명문 수집(README 앞 8KB / 레지스트리 description / npm description)
   ③ facts                 bundle + official_text → 사실 목록(코드)
   ④ claim_check           Claude: 주장별 일치/불일치/확인불가 + 원문 구절 위치 → 코드가 구절 실재 검사
   ⑤ grade                 §1 표를 코드로 적용(LLM 없음)
   ⑥ owner (나일 때만)     workflow.yaml + 결과 → 판정 B, 카드 초안   → owner.json (bundle과 분리)
   ⑦ reply                 코드 템플릿 2통, 통별 전송 상태
```
- 등급은 코드가 정한다(⑤). LLM은 ④의 주장 대조만 한다 → 인젝션이 성공해도 할 수 있는 일은 특정 주장을 `확인 불가`로 바꾸는 정도. `일치`/`불일치`는 공식 원문에 구절이 실제로 있어야 인정

## 3. 구성 요소
### 3-1. 추출 확장 (`extract.py`)
- 엔티티마다 `claims`: 그 도구에 대한 캡션·전사 속 주장 최대 3개(원문 구절, 코드가 원문 포함 여부 검사)
- Claude API 어댑터 추가(LM Studio 유지). 추출 실패와 "도구 없음"을 구분해 bundle에 기록(Codex #4)

### 3-2. 공식 문서 수집 (`official.py`, 신규 측정)
- GitHub 레포: README 앞 8KB + repo description (`gh api GET`, runner 허용 목록 안)
- npm: package description·homepage
- 원격 MCP: 레지스트리 항목의 description·repository·websiteUrl을 **resolve 단계에서 버리지 말고 보존**(현재는 버림 — Codex #1)
- 전부 `<untrusted>` 데이터. 판정 시점(수집 시각)을 기록

### 3-3. 사실 목록 (`facts.py`, 코드)
- 사실 = `{id, kind, text, source, measured_at}`. 측정 note(예: 기여자 100명까지만 읽음)를 문구에 포함(Codex #1 기여자 표본)
- §1 필수 증거 각각을 boolean으로 계산하고, 미충족 사유도 사실로 남긴다

### 3-4. 주장 대조 (`claims.py`, Claude)
- 입력: 주장 목록(id), 공식 원문(문단 번호 붙임)
- 출력 JSON: `[{claim_id, result ∈ 일치/불일치/확인불가, paragraph, quote(≤120자)}]`
- 코드 검증: `quote`가 해당 문단에 **글자 그대로** 있는지, `일치/불일치`인데 quote가 없으면 `확인불가`로 강등. 실패 2회 → 전부 `확인불가`

### 3-5. 등급 (`grade.py`, 코드) — §1 표 그대로. 표 밖 판단 없음

### 3-6. 내 모드 (`owner.py`)
- 정본 `~/.config/hype-checker/workflow.yaml`(600): 항목마다 `id`(레포·패키지·URL 정본), `aliases`, `capabilities`(기능 한두 줄), `lane`, `status`(active/trial/retired), `note`(예외)
  - 첫 버전: Claude가 research `workflow-adoption.md`·`log.md` 판정 B·`~/Ops/domains`·설치 목록에서 **초안을 만들고 사람이 승인**
  - `hype-check snapshot`은 설치 목록을 훑어 "정본에 없는 항목"만 제안(자동 반영 안 함)
- 판정 B
  - 정본의 `id`나 `aliases`와 일치 + `status=active` → `이미보유`(규칙)
  - `retired`와 일치 → `불필요(과거 폐기: note)`
  - 그 외 Claude: 정본의 `capabilities`와 비교해 `이미보유(기능 중복: 항목 id)/후보/불필요`. `채택`은 자동으로 주지 않는다(채택은 사람이 결정 — 카드 초안에 "후보"로)
  - 👎이면 `후보` 이상 금지
- **격리(런타임)**: owner 결과는 `owner.json`에만 쓰고 bundle에 넣지 않는다. 손님 답장 생성 함수는 owner 데이터를 인자로 받지 않는다. 판정 결과·프롬프트 캐시를 발신자 간에 공유하지 않는다. 테스트: `workflow.yaml`에 카나리 문자열을 넣고 손님 경로 전체 출력(답장·bundle·로그)에 없음을 확인(Codex #5)
- 카드 초안 `out/<case>/card.md`: 콘텐츠 1건 = 카드 1장(도구는 카드 안 목록). 출처 = "DM 공유 · media_id · 공유 시각"(원 게시물 링크는 API로 못 얻으면 `링크 미기록`으로 두고 사람이 채움), 판정 A 빈칸, 판정 B 자동값, "실행한 명령: 없음(자동 측정만)"

### 3-7. 답장 (`reply.py`, `labels.py` 공용)
요약(1통째) 예 — 등급은 형식을 보이려는 가상의 값:
```

4. "Lazyweb" · MCP 서버 — ❔ 판정 보류
```

- 내 모드는 요약 아래에 `내 워크플로우: 이미보유(기능 중복: pptx-from-layouts) / 후보 …`와 카드 초안 경로

## 4. 운영·비용
- **항목 단위 처리**: loop는 큐에서 하나 꺼내 처리하고 바로 전송한다(backlog가 앞 항목의 전송을 막지 않음). 항목 마감 180초, 넘으면 그때까지의 결과로 ❔ 처리
- **전송 상태**: `messages: [{text, sent, attempted_at, error}]`. 통별 최대 1회(v2 원칙), 1통 성공·2통 실패면 2통만 재시도 대상. 429는 지수 대기(최대 3회) 후 포기 기록
- **상한(파일에 날짜별 카운터, 재시작에도 유지, 실패 호출 포함)**
  - 항목당: 판정 대상 도구 최대 6개(나머지는 "외 N개 생략"), Claude 호출 최대 8회, 입력 토큰 최대 40K
  - 발신자당 하루 20건, 전체 하루 100건, 하루 Claude 비용 추정 상한 $2 — 넘으면 **측정도 하지 않고** "오늘 한도에 도달했어요" 한 줄
- **Claude 장애**: 추출 실패 → "지금은 처리하지 못했어요. 잠시 뒤 다시 보내 주세요"(도구 없음과 구분). 주장 대조 실패 → 해당 주장 `확인 불가`로 계속(등급은 코드라 계속 나옴)
- **재현 기록**: 판정마다 모델명·프롬프트 해시·규칙 버전·workflow.yaml 해시·사용 사실 id·토큰·비용을 bundle(`verdict` 블록)·owner.json에 남긴다

## 5. 보안·프라이버시
- 캡션·README·레지스트리 설명은 `<untrusted>`. LLM 출력은 enum + 원문 구절 위치만 통과(D4)
- Anthropic으로 가는 데이터: 캡션, 공개 공식 문서, (내 모드) workflow.yaml의 `capabilities`·`lane`. 비밀값·설치 경로·토큰은 보내지 않는다
- PRIVACY.md 갱신 후 손님 자동 판정 켜기(D13)
